# 재도킹 검증 게이트 — 판정과 근거 (spec §7.4)

**판정: 두 양성자화 상태 모두 FAIL.** 실패 기준은 (c) 대칭보정 RMSD 하나뿐이다.

| 기준 | 중성 | 음이온 | 문턱 |
|---|---|---|---|
| (a) 카복실레이트 O → Ca501 | 2.57 Å pass | 2.51 Å pass | ≤ 3.2 Å |
| (b) 도너 → β1-Asn224 backbone O | 2.81 Å pass | 2.81 Å pass | ≤ 3.5 Å |
| (c) 대칭보정 RMSD (`CalcRMS`) | **2.15 Å FAIL** | **2.15 Å FAIL** | < 2.0 Å |
| (d) PLIP Ca501 금속 배위 | pass | pass | 필수 |
| (d) PLIP Asn224 수소결합 | pass | pass | 필수 |

원자료: `results/v2_redock_gate.md`, `results/v2_redock_gate_anion.md` (포즈 20개 전체 표 포함).

## 2.15 Å이 실재하는 값임을 확인한 경로

이 숫자가 캠페인 전체의 방향을 정하므로, 측정 인공물 가능성을 하나씩 배제했다.

1. **PLIP 금속 사이트 분리** — 초기 실행에서 기준 (d)가 2.57 Å 접촉에 대해 실패했다. PLIP 자신의 `METAL_DIST_MAX`가 3.0 Å이므로 화학이 아니라 인공물이었다. 원인은 `poses_to_complex.py`가 `LINK` 레코드를 쓰지 않아 PLIP이 리간드와 칼슘을 별도 사이트로 본 것(커밋 `aa1155a`), 그리고 LINK을 쓴 뒤에도 리간드 체인이 공백이라 PLIP이 링크를 폐기한 것(커밋 `04c7f35`). 수정 후 (d)는 두 아암 모두 통과한다.
2. **입체화학** — 대조군이 SMILES에서 재생성되어 거울상이 뒤집혔을 가능성을 검토했다. `write_control_shard`는 결정 좌표 SDF를 직접 읽고 수소만 `addCoords=True`로 붙이며(중원자 변위 0.000000 Å), 참조 SMILES는 `[C@@H]`로 입체가 정의되어 있다. 해당 없음.
3. **양성자화** — spec §7.4가 등록한 두 상태 중 음이온 쪽이 실행되지 않았음을 발견하고 실행했다(커밋 `cbe5995`). 두 상태 모두 2.15 Å.
4. **그래프 불일치** — Open Babel이 `.dlg` 포즈를 SDF로 변환하며 카복실레이트를 재양성자화해, 참조(`C(=O)[O-]`)와 포즈(`C(=O)O`)의 부분구조 일치가 0건인데도 `CalcRMS`가 값을 반환하고 있었다. 양쪽을 같은 변환기로 통과시키고 그래프 불일치 시 숫자를 내지 않도록 고쳤다(커밋 `42cc18c`). 값은 2.15로 동일.
5. **원자 대응 직접 확인** — `.dlg` 포즈는 입력 PDBQT의 원자 순서를 보존한다(원자 이름 순서 일치 확인). 그래프 매칭 없이 인덱스 대응으로 계산한 중원자 RMSD는 **2.258 Å**이고, `CalcRMS`의 대칭 보정이 이를 2.15로 낮춘다. 대칭 보정은 값을 낮추기만 하므로 두 값은 일관된다.

AutoDock `.dlg`의 `Reference RMSD` 열은 같은 포즈를 1.46 Å으로 적는다. 위 5번이 제1원리에서 검증한 값과 어긋나므로, 이 열이 무엇을 재는지는 별도 사안으로 두고 본 판정에는 쓰지 않는다. 참고로 두 측정은 다른 포즈들에 대해서는 일치한다(예: run 5, 0.55 대 0.56).

## 실패의 성격 — 샘플링이 아니라 순위

AutoDock-GPU는 결정 포즈를 **정확히 재현한다**. 20개 런 중:

- 중성: 16개가 RMSD 0.51–0.54 Å
- 음이온: 10개가 RMSD 0.53–0.57 Å

실패는 AD4 점수함수가 ~2.1 Å 대체 포즈를 0.5 Å 포즈보다 **0.25–0.28 kcal/mol 높게** 매기는 데서 온다(중성 −6.77 대 −6.50, 음이온 −7.81 대 −7.53). AutoDock 자신의 클러스터링은 20개 런을 단일 클러스터(Rank 1)로 묶고 그 대표를 2.15 Å 포즈로 지정하므로, 클러스터 점유수로 다른 포즈를 고를 여지는 없다.

## 기하 기준이 두 포즈를 구별하지 못한다

§8.5b의 두 기하 기준은 **양쪽 클러스터를 모두 통과시킨다**. 2.15 Å 포즈도 Ca501 2.51 Å, Asn224 2.81 Å로 기준 안에 있고 PLIP도 두 상호작용을 모두 보고한다. 즉 "기하로 포즈를 고른다"(§9.1)는 규칙만으로는 결정 포즈와 2.15 Å 대체 포즈가 갈리지 않는다. 이 한계는 이 게이트가 아니었으면 드러나지 않았을 것이며, 리드 보고서에 명시해야 한다.

## 비교 대조군 — v1 엔진

v1의 Uni-Dock/smina 재도킹 포즈(`docking/redock_poses.sdf`)를 동일한 `CalcRMS`로 재측정한 결과:

| 엔진 | 상위 포즈 affinity | 상위 포즈 RMSD | §7.4 판정 |
|---|---|---|---|
| Uni-Dock / Vina (v1) | −6.91 | **0.63 Å** | 통과 |
| AutoDock-GPU / AD4 (v2, 중성) | −6.77 | **2.15 Å** | 실패 |
| AutoDock-GPU / AD4 (v2, 음이온) | −7.81 | **2.15 Å** | 실패 |

이 리간드에 한해, 재도킹 재현성에서는 Vina가 AD4보다 낫다.

## 사전등록된 처리와 그 비용

> 미통과 시 **AutoDock-GPU로 어떤 것도 순위 매기거나 거르지 않으며**, Uni-Dock 체제로 복귀하고 그 사실을 기록한다. (spec §7.4)

비용을 숨기지 않고 적는다: Uni-Dock의 Vina 점수함수에는 **금속 배위 항이 없다.** blueprint가 반복해서 인정한 최대 결함이고(*"Vina has no metal coordination term at all"*), v2가 엔진을 교체한 이유 자체다. 복귀는 재도킹 재현성을 얻는 대신 그 결함을 되돌린다.

다만 기하 필터(§8.5b)는 v1·v2 양쪽에서 유지되므로, MIDAS 배위는 점수함수가 아니라 기하 기준으로 계속 강제된다. 위 "기하 기준이 두 포즈를 구별하지 못한다" 항목이 그 강제력의 한계를 규정한다.

## 결정 (2026-09-29)

**사전등록대로 Uni-Dock 체제로 복귀한다.** 규칙과 증거가 같은 방향을 가리킨다 — 이 리간드에 대해 Vina는 0.63 Å, AD4는 2.15 Å이다.

AutoDock-GPU로 이미 산출한 포즈(TL-A′ 4,514, TL-C 5,212)와 PLIP 레코드는 **폐기하지 않고 보존한다.** 사전등록은 "순위 매기거나 거르는 데 쓰지 말라"고 했을 뿐 기록을 버리라고 하지 않았으며, 두 엔진의 기하 게이트 통과율 비교는 그 자체로 보고 가치가 있다. 리드 선정에는 쓰지 않는다.

### 복귀 시 반드시 지킬 것

**Uni-Dock에도 같은 게이트를 적용한다.** 위 0.63 Å은 **smina**로 측정한 값이다. Uni-Dock v1.1.3은 점수함수가 같을 뿐(`--scoring` 기본값 `vina`) 구현과 탐색(GPU 병렬 Monte Carlo)이 다르다. smina 결과를 근거로 Uni-Dock을 채택하는 것은 이번에 AD4에서 저지를 뻔한 것과 같은 종류의 비약이다. `validate_redock.py`가 이제 `--poses`로 Uni-Dock 출력 PDBQT를 읽으므로 동일 기준·동일 문턱으로 판정할 수 있다.

**affinity 하드 필터의 기준값을 다시 산출한다.** §9.1의 PLN-1474 상대 필터는 같은 엔진·같은 박스에서 나온 값이어야 한다. AD4로 얻은 어떤 기준값도 Vina 점수에 쓸 수 없다.

**기하 기준의 한계를 리드 보고서에 명시한다.** 위 "기하 기준이 두 포즈를 구별하지 못한다"는 엔진을 바꿔도 사라지지 않는다. 기하 게이트 통과가 결정 결합 양식의 재현을 보장하지 않는다는 사실이 이번 게이트의 가장 이전 가능한 소득이다.

# Uni-Dock 게이트 결과 (2026-09-29)

채택 후보 엔진에 **같은 기준·같은 문턱**으로 게이트를 적용했다. v1의 0.63 Å은 smina로 잰 값이고 Uni-Dock v1.1.3은 점수함수만 같을 뿐 구현과 탐색이 다르므로, 그 숫자로 채택할 수 없었다.

| 기준 | 중성 | 음이온 | 문턱 |
|---|---|---|---|
| (a) 카복실레이트 O → Ca501 | 2.61 Å pass | 2.71 Å pass | ≤ 3.2 Å |
| (b) 도너 → β1-Asn224 backbone O | 2.90 Å pass | 2.89 Å pass | ≤ 3.5 Å |
| (c) 대칭보정 RMSD | **0.66 Å pass** | **0.63 Å pass** | < 2.0 Å |
| (d) PLIP Ca501 금속 배위 | pass | pass | 필수 |
| (d) PLIP Asn224 수소결합 | pass | pass | 필수 |

**판정: 두 상태 모두 PASS. Uni-Dock을 이 캠페인의 도킹 엔진으로 채택한다.**

원자료: `results/v2_redock_gate_unidock_neutral.md`, `results/v2_redock_gate_unidock_anion.md`.

## 양성자화 선택 — 음이온

spec §7.4 원문: *"둘 다 재현하면 **음이온**을 택한다 — pH 7.4의 실제 존재 형태이고, 점수함수가 이제 전하를 본다."* 두 이유 중 앞의 것은 엔진과 무관하므로 엔진 교체 후에도 유효하다.

Vina에 명시적 쿨롱 항이 없다는 이유로 이 규칙을 뒤집으려 했으나(런북 이전 판), 성립하지 않는다. 전하 상태는 Vina 점수에 실제로 닿는다 — 카복실레이트가 되면 COOH 회전결합이 사라져 비틀림 수가 6에서 5로 줄고 수소결합 원자 유형이 바뀐다. 측정값도 갈린다(중성 −6.718, 음이온 −6.913). 원문 규칙을 따른다.

## 엔진 비교 — 같은 게이트, 같은 리간드, 같은 문턱

| 엔진 | 상태 | 상위 포즈 affinity | 상위 포즈 RMSD | 판정 |
|---|---|---|---|---|
| AutoDock-GPU / AD4 | 중성 | −6.77 | 2.15 Å | 실패 |
| AutoDock-GPU / AD4 | 음이온 | −7.81 | 2.15 Å | 실패 |
| Uni-Dock / Vina | 중성 | −6.72 | 0.66 Å | 통과 |
| Uni-Dock / Vina | 음이온 | **−6.91** | **0.63 Å** | **통과 (채택)** |

AD4 점수는 Vina 점수와 비교할 수 없으므로 affinity 열은 엔진 간 비교에 쓰지 않는다.

## 기록해야 할 한계 — 포즈 수

Uni-Dock은 `--num_modes 20`, `--energy_range 10.0`, `--min_rmsd 0.5`에서도 대조군에 **중성 2개, 음이온 4개**의 포즈만 반환했다. AutoDock-GPU는 같은 리간드에 20개를 냈다.

이 대조군에 한해서는 문제가 아니다 — 반환된 포즈가 **전부** 결정 포즈이기 때문이다(RMSD 0.63–0.66 Å). 오히려 Uni-Dock의 수렴이 조밀하다는 뜻이다.

그러나 §8.5b의 전략은 *"포즈를 많이 만들어 기하로 고른다"*이고 그 근거는 점수함수에 금속 항이 없다는 것이다. 리간드당 포즈가 2–4개면 기하 선택이 작동할 여지가 좁다. 생성 분자에서 리간드당 실제 포즈 수를 집계해 리드 보고서에 보고한다. 본 게이트 판정 이후에 측정하며, 판정 전에 클러스터링 파라미터를 건드리지 않는다.
